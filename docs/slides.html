Structure

The prompt is the decisions

Extract ONLY what is printed; never invent or infer facts. events: one object per distinct posting. EXPLODE compound clauses into separate events. place: as printed. If the clause names no place, carry over the previous clause’s place and set place_inherited=true. birth_year: only if explicitly printed. NEVER infer from the earliest career date. honours: with their award year if printed in parentheses; award-years are NOT career events.

Every rule exists because a run broke it.

Python grammar first; refuses what it cannot fully parse. Then Qwen3.6-35B-A3B on a university GPU, reasoning off, temp 0: 30,496 entries in 8.24 hours, one a second, 55 failures. Then a Python validator and a post-normaliser.

Clean

Forty editions, one person

A missed link is recoverable; a false merge silently corrupts the record. Ties resolve to no merge.

  1. Deterministic passes: 0 false merges on 543 hand-verified careers
  2. Cluster the residue: shared forename + surname suffix, so OCR variants meet
  3. A model argues each cluster from a dossier; the reason goes in a ledger (917 so far)
  4. A 200-case silver standard, afterwards, to measure it

Ground

Why

Every arc needs coordinates for “the Central Provinces”, “British Guiana”, “Jodhpur”. Wikidata has the item, the coordinates, or the capital that has them. One query.

And: a historian of the Cape and a historian of Bombay who both ground to Q1800510 have joined their data without meeting.

Two ways to get a QID. Retrieve it, read the item, gate it. Or ask a chatbot.

Live: the lookup

  1. “Henry Trimen botanist Ceylon Peradeniya” → read the statements → supported
  2. “Ferdinando Hamlyn Price” → Q123279571, alias Hamlyn, b. 1855, d. 1942, Tamil description only → supported, and the pipeline’s gate had rejected it
  3. “Elwood D’Arcy Tibbits Antigua” → nothing → unresolved, record the search

WikidataMCP vector search. Saved results in outputs/ground-test/ if the network fails.

All three chatbots read the entry right. The difference is where the number came from, and the cost. 27 minutes for 20 entries is 25 days for the Colonial Office List. The retrieval columns are the review queue, not the corpus. Even the best column needs you: which Gorges? Is Harris b. 1858 the Harris b. 1855?

Six Victorias

The Australian colony. The capital of British Columbia. An electoral district. A gaol in Hong Kong. A district in the Cape. A county in Mauritius. A town in the Seychelles.

Surface-keyed cache → one QID for everyone. Context resolver → per person. Six surfaces left ungrounded on purpose.

Fix the rule, re-emit both corpora, rebuild the atlas, look at everyone the rule touched.

What the map cannot find

False negatives. An ungrounded “Victoria” has no arc. A missed merge is two plausible short careers.

For those: silver standards. 200 hand-labelled cases, risky strata oversampled. Rare surname + overlapping era: the judge’s “different” verdicts were wrong 76% of the time.

Your own data

  • One question, one small sample, the page reachable.
  • Build the view early. It is your error detector.
  • Local identifiers first. External ones after retrieval and review. None from memory.
  • Ground to the historical entity. Resolve per person, not per string.
  • Ties resolve to no merge.
  • Fix the rule, not the record; make the correction a test.
  • Two kinds of model. A frontier model writes the pipeline; a cheap one reads the collection inside it.
